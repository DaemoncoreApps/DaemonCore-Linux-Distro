Web application testing

Use a localhost application or deliberately vulnerable lab.

Guidebook homeLab setup
Automated web tools can create many requests, alter data, or trigger account lockouts. Keep the target local until you understand each option and have explicit authorization.

Create a harmless local target

mkdir -p ~/lab-site/admin
printf '<h1>DaemonCore local lab</h1>\n' > ~/lab-site/index.html
printf 'Local test page\n' > ~/lab-site/admin/index.html
python3 -m http.server 8000 --directory ~/lab-site

Open http://127.0.0.1:8000 in Firefox. Stop the server with Ctrl+C.

Inspect before automating

  • Browse normally and note pages, inputs, cookies, redirects, and error handling.
  • Use Firefox developer tools to inspect requests and responses.
  • Record the expected behavior before looking for unexpected behavior.

Practice content discovery locally

printf 'admin\nbackup\nstatus\n' > ~/lab-words.txt
ffuf -u http://127.0.0.1:8000/FUZZ -w ~/lab-words.txt -rate 5
gobuster dir -u http://127.0.0.1:8000 -w ~/lab-words.txt --delay 200ms

The low rate and small wordlist make behavior easy to understand. Do not aim large public wordlists at a remote service without agreed rate limits.

Review findings

For each issue, capture the minimum request and response needed to reproduce it. Remove session tokens and personal data from reports. Prefer a safe proof of impact over extracting data or changing server state.
