Build a safe lab

Contain experiments before opening a security tool.

Recommended layout

Run DaemonCore and the practice target as separate virtual machines. Put both on an isolated, host-only virtual network. Do not bridge a deliberately vulnerable target to a home, school, or business network.

SystemPurposeNetwork
DaemonCore VMWorkstation and evidence collectionHost-only; temporary NAT only for updates
Practice targetDeliberately vulnerable training systemHost-only only
Host machineSnapshots and recoveryKeep normal network separate

Pre-flight checklist

  • Take clean snapshots of both VMs.
  • Confirm the target cannot reach the internet or other LAN devices.
  • Write the exact target IP address and allowed test types.
  • Set a time limit and define what should immediately stop the test.
  • Never use personal passwords, tokens, or production data in the lab.

Create an engagement folder

mkdir -p ~/engagements/lab-01/{notes,scans,captures,evidence}
date -Is | tee ~/engagements/lab-01/notes/start-time.txt
ip addr | tee ~/engagements/lab-01/notes/daemoncore-network.txt

Keep raw output unchanged. Add interpretation in a separate notes file so another person can distinguish evidence from conclusions.

Recovery

When finished, power off the target and revert its snapshot. Remove test data from the DaemonCore VM only after retaining the evidence required by the lab or engagement owner.
