Password auditing

Measure password policy using test material you created yourself.

Guidebook homeLab setup
Password hashes can still be sensitive. Never copy an organization's credential database without written authorization, approved storage, and a deletion plan.

Create a disposable exercise

printf 'daemoncore-lab' | sha256sum | cut -d' ' -f1 > ~/lab-sha256.txt
printf 'not-the-password\ndaemoncore-lab\nexample-only\n' > ~/lab-wordlist.txt

On DaemonCore, identify the saved test hash with:

hashid "$(cat ~/lab-sha256.txt)"

Audit the test hash

hashcat -m 1400 ~/lab-sha256.txt ~/lab-wordlist.txt
hashcat -m 1400 ~/lab-sha256.txt --show

This bounded dictionary test demonstrates why predictable phrases fail. Avoid unbounded brute force: establish time, energy, hardware, and data-retention limits before a real audit.

Turn results into policy

  • Prefer long, unique passphrases over composition tricks.
  • Use a password manager and phishing-resistant MFA where possible.
  • Store passwords with a modern, salted, deliberately slow password hash.
  • Report aggregate results; do not publish recovered passwords.
  • Delete working copies and recovered material on schedule.
